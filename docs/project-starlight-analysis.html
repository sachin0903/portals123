TL In one paragraph

Project Starlight is the Futura build — a signed engagement (~£350k ex VAT, 16-week Phase 1) to deliver Futura Financial Services Group a single-tenant, Futura-branded digital advice operating system with the same client / adviser / admin surfaces as the Graphene portals. It is not a literal copy of the multi-tenant codebase; it is the single-tenant, branded sibling that reuses ~75–80% of the shared portals engineering (auth, data model, workflow, fact-find, risk, documents, the three portals). The genuinely Futura-specific work is small: SmartSearch ID/AML, the Futura letter/suitability templates, branding, and the single-tenant deploy + pilot.

The PS Jira board is bimodal: the 14-epic spine and the discovery/POC work are real, valuable BA output, but the ~83 build stories are largely auto-generated skeleton (only 21 of ~110 issues carry acceptance criteria). The deeper issue is scope: PS frames Starlight as a from-scratch standalone app, duplicating capabilities the portals already provide. Recommendation: build Starlight as a single-tenant config/branding overlay on the portals — represented now in the roadmap, TECH Jira and Confluence.

5 Recommendations & open decisions

1 · Build Starlight as an overlay, not a rebuild. Deploy the shared portals engineering single-tenant + re-skinned for Futura. Only SmartSearch, the Futura templates, branding and the single-tenant deploy/pilot are net-new. This is the £-saving decision — not the ticket cleanup.
2 · Treat the PS story layer as waste. The epics and specs are real; the ~83 build stories can't drive a sprint (no AC / estimates / owners). Regenerate against real engineering tasks or close them.
3 · Check the commercial vs scope fit. 14 epics / ~83 stories (two portals + workflow engine + suitability + e-sign + go-live) is multi-quarter scope priced/timed as one 16-week phase. Confirm Phase 1 ⊂ that scope.
4 · Housekeeping. TECH stories were created at To Do (real state is in each description) — transition the ~12 in-progress/foundation ones to match the roadmap when convenient. The roadmap-v2.html edit is uncommitted, for review.
