1 What it is & how it's delivered

Project Starlight is the Futura build — a single-tenant, Futura-branded digital advice OS for Futura Financial Services Group (trading styles Whitefriars, CB Financial Advisers, Futura Wealth Management, Bulley Davey). Signed engagement, ~£350k ex VAT, 16-week Phase 1 (4 weeks discovery — done — + 12 weeks dev). Futura owns the system & IP. Same client / adviser / admin surfaces as the Graphene portals; Phase 1 = digital onboarding + LVP advice.

Literally a copy of the core portals, stripped to one tenant. The workflow engine, applications and the onboarding / fact-find flow are core — built for the normal Tav / CR / ML portals anyway — so Futura doesn't pay for them. PD3 builds the base (copy + strip + branding + cases + messaging → base go-live late Sep); then PD1 and PD2 join after their portals work (~14 Sep) to build the features additional to Futura — doc-gen (engine + suitability + letters), PEP/EDD, paraplanner + compliance views, and MI / reporting. Net Futura-specific ≈ 9.5 ew across the squad; full Phase-1 ~mid Oct.
Validated against the Phase-1 Requirements Summary (Futura sign-off; go-live target 29 Aug 2026). Two deltas: (1) the 29 Aug target is at risk under current sequencing — Futura is built after the core portals and the workflow engine lands mid-Sep, so the realistic base go-live is late Sep (full ~mid Oct); (2) PEP/EDD, the MI/reporting database and dedicated paraplanner/compliance pages are Phase 2 in the signed summary — carried here as an explicit Phase 1.5 stretch (pulled forward), not part of the signed Phase-1 scope. Templated SR generation is correctly Phase 1.

2 Features (Phase 1)

Grounded in the locked Starlight specs. Principle: "advisers see, admins do"; online / offline / mixed capture modes (a case can run invite→completion with zero client logins).

Client portal

  • Invite → account setup → welcome pack
  • Documents — review & e-sign
  • ID verification (photo ID + selfie + PoA)
  • "Your Details" fact-find (9 sections)
  • Risk profile → suitability summary
  • Secure messaging · notifications
  • "How can we support you?" (vulnerability)
  • Save-&-resume · jargon tooltips · Consumer-Duty signposting

Adviser portal

  • Pipeline / applications dashboard
  • Case record — vulnerability & key-notes banners, workflow chain, LOAs, tasks, client history
  • Fact-find review — soft-facts, rationale, edit-on-behalf, request-changes
  • Risk review — override + rationale
  • ID/AML review — auto (SmartSearch) + manual override / declaration of likeness
  • Document & suitability review

Admin portal

  • Case creation (auto-invite, seeds first task)
  • Task queue — the central work surface
  • Document mgmt — templates / issue / chase / classify
  • LOA mgmt — cross-case queue, paper branch
  • ID/AML mgmt — SmartSearch, manual escalation
  • Vulnerability / key-notes; account opening
  • Configurability — advisers/firms, templates, provider directory, routing rules, taxonomies, AML & notification settings

5 Dependencies & notes

  • Validated against the Phase-1 Requirements Summary (Futura sign-off, go-live target 29 Aug 2026). 29 Aug is at risk under the current after-portals sequencing (workflow engine lands mid-Sep) — realistic base go-live late Sep, full build ~mid Oct. Recommend a replan / re-baseline conversation with Futura.
  • Two waves. PD3 builds the base once the core portals are stable (~31 Aug) → base go-live late Sep. PD1 and PD2 join after they finish their portals work (~14 Sep) to build the features additional to Futura, so full Phase-1 lands ~mid Oct. No late engine gate — the workflow engine lands mid-Sep.
  • Workflows / applications / onboarding are core, not Futura. The normal Tav/CR/ML portals need the workflow engine, account applications and the onboarding / fact-find flow anyway, so they're built once for everyone and Futura reuses them free. That's why the Futura-specific figure is only ~4.5 ew — branding + doc-gen + cases + messaging + the single-tenant copy. Cases and messaging (not needed for custody go-live) are the only genuinely advice-specific builds, and they're reusable by any future advice tenant.
  • Provider = SmartSearch (Futura's choice) wired onto the shared, provider-agnostic ID/AML framework — CreditSafe / iDenfy remain available for other tenants. PEP/EDD is Phase 2 (binary result first).
  • Branding: Futura is the dominant brand; trading-style sub-brands appear only on the "Your Adviser" card (inherited from the assigned adviser's firm); invites from portal@futurafs.com.
  • Phase 1.5 (pulled forward from Phase 2 — PD1/PD2 after portals): PEP/EDD, paraplanner + compliance views, MI/reporting DB. The signed Phase-1 summary places these in Phase 2; they are carried here as an explicit stretch, not signed scope. Templated SR generation is Phase 1 (in scope). Still Phase 2: tailored/bespoke SR, real-time collaborative SR editing, dedicated Paraplanner & Compliance portals, account-opening platform integration.
  • PS Jira board left untouched — this plan is tracked via the roadmap FT-* group and TECH-32; the legacy PS backlog is unchanged.
