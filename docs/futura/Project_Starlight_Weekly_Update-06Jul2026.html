Project Summary

Starlight is built on Graphene's shared multi-tenant platform — the same engineering that powers our other client portals — delivered to Futura as a single-tenant, Futura-branded instance. This week the shared foundation that Starlight reuses moved on materially: per-tenant white-label branding (with a visual branding studio and live portal preview) and the multi-tenant identity / access / operations platform. Net effect: the Futura-branded look becomes a configuration, not a code fork. The next milestone is the shared advice engines — workflow, forms (fact-find / risk), and ID/AML — which the Futura onboarding journey sits on.

🚧 Key actions & review areas

POC sign-off still open (Futura). EPIC 0b (POC iteration & UX sign-off) remains the current gate — Futura feedback rounds + module UX sign-offs. Closing this unblocks the onboarding-journey build.
Sequencing. The Futura onboarding journey (invite → documents → ID/AML → fact-find → risk → suitability) depends on the shared advice engines above. Those land next; the Futura-specific build starts once they're in place — see resourcing note below.
Good news on cost. With the branding studio delivered, the Futura re-skin of the three portals is now largely configuration, not bespoke build — reducing the Futura-specific effort.

📋 Key decisions & notes

  • Reuse, not rebuild. Starlight is a single-tenant, Futura-branded instance of the shared platform — auth, tenancy, branding, RBAC and the operations portal are now in place and reused, not rebuilt.
  • ID/AML is provider-agnostic. The shared framework takes pluggable providers; Futura's choice (SmartSearch) is a thin adapter on top — swappable later.
  • Branding as configuration. Futura's look is set in the studio (colours, logos, layout) with a live preview — no code fork per firm.
